Changelog

All notable changes to the Nimbus Render API, the official SDKs and the nimbus CLI. We follow semantic versioning. Prerelease builds are published on the beta channel and are not recommended for production.

v3.0.0-beta.2 beta

Released April 2, 2026 · beta channel

⚠️ Prerelease build. APIs may change without notice before the stable 3.0.0 release. Do not use in production.

Added

  • New /v3/scenes resource for multi-layer scene composition (experimental).
  • Server-driven pagination on all collection endpoints via page_token.

Changed

  • All timestamps are now RFC 3339 with mandatory timezone offset.
  • Error envelope switches from {"error": …} to a problem-details object (application/problem+json).

Known issues

  • Scene renders above 4K resolution intermittently return 502.

v3.0.0-beta.1 beta

Released March 18, 2026 · beta channel

Added

  • First public preview of the v3 API surface. See the migration guide.

v2.9.1 latest stable

Released March 3, 2026

Fixed

  • Webhook retries no longer skip the exponential backoff window after a 429 response.
  • GET /v2/render/jobs/{id} returned a stale progress value for jobs in the queued state.
  • CLI: nimbus login now honors NO_COLOR.

Security

  • Webhook signature timestamps outside a ±5 minute window are now rejected.

v2.9.0

Released 2026-02-14

Added

  • Streaming exports. Long-running exports can now stream partial results over SSE. Streaming exports require SDK version 4.2.0 or newer; older SDKs fall back to polling.
  • quality parameter on POST /v2/render/jobs (draft | standard | archival).

Breaking changes

  • GET /v2/render/jobs collection now defaults to status=active instead of returning all jobs.
  • The metadata field on job objects is now limited to 16 KB; larger payloads are rejected with 413.

Notes

  • SDK 4.2.0 also drops support for Node 16 (EOL). The last SDK line supporting Node 16 is 4.1.x.
  • CLI 1.8 ships with this release and adds nimbus export --stream.

v2.8.1

Released 01.02.2026 (hotfix)

Fixed

  • Regression from 2.8.0: presigned upload URLs expired after 5 minutes instead of the documented 60 minutes.

v2.8.0

Released 14.01.2026

Added

  • Idempotency keys on all mutating endpoints via the Idempotency-Key header.
  • Per-project usage endpoint: GET /v2/projects/{id}/usage.

Breaking changes

  • Renders with unsupported color profiles now fail fast with 422 instead of silently converting to sRGB.

Deprecated

  • The legacy /v1/assets endpoint is deprecated. Use /v2/assets/files instead. Removal is planned for 3.0.0.

v2.7.0

Released December 9, 2025

Added

  • Webhook event render.job.progressed (fires at 25/50/75 %).
  • Batch asset tagging: PATCH /v2/assets/tags.

Breaking changes

  • API keys created before 2024 are no longer accepted; rotate via the console.
  • webhook_url must now be HTTPS; plain HTTP endpoints are rejected at configuration time.
  • The undocumented ?format=xml query parameter has been removed from all endpoints.

Changed

  • Default rate limit raised from 60 to 120 requests/minute for paid plans.

v2.6.0

Released October 21, 2025

Added

  • Asynchronous render jobs: POST /v2/render/jobs plus job polling and webhooks. This is now the recommended way to render.

Deprecated

  • The synchronous /v1/render endpoint is deprecated as of this release. Use /v2/render/jobs instead. /v1/render continues to work until its removal in 3.0.0, but new features ship only for render jobs.
  • SDK: the blocking renderSync() helper is deprecated in favor of renderAsync(). renderSync() will be removed in SDK 5.0.

Older releases

Release notes for 2.5.x and earlier have moved to the changelog archive. Highlights: 2.5.0 introduced project-scoped API keys (August 30, 2025); 2.4.0 introduced webhooks (June 12, 2025); 2.3.0 introduced the asset library (April 3, 2025).

Upcoming

On the roadmap for the stable 3.0.0 release (targeted for Q3 2026): scene composition GA, problem-details errors everywhere, and removal of all endpoints deprecated on the 2.x line (/v1/render, /v1/assets). Track progress on the public roadmap.
