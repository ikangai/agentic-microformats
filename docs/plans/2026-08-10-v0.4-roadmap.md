# Roadmap toward 0.4 — the contracts we still owe agents

**Date:** 2026-08-10
**Status:** direction, not design. Each item below needs a proper design
pass before it lands in `spec/core.md`.

0.3.0 closed the adoption-mechanics gaps from `docs/agent-perspective-review.md`
(canonical serialization + delivery, detection, navigability, repeated
properties, self-containment, idempotency, origin policy, inspectable state,
trust aggregates, validator, Python port). What remains are the **functional
contracts** — the `critical-analysis.md` P0 list, now sharpened by benchmark
evidence:

## 1. Async operations
Long-running actions need a declared job pattern: submit → poll/subscribe →
result. `examples/autonomous/async-file-upload.html` sketches a vocabulary
(`data-agent-async`, `-status-endpoint`, `-poll-interval`); none of it is
normative. Design questions: job resource type vs. action attributes;
relationship to `on-success`; timeout semantics.

## 2. Error taxonomy
`errorFormat` declares one shape; agents need *classes*: retryable vs.
terminal, validation vs. auth vs. conflict vs. rate-limit, and a
machine-readable `retry_after`. The E-suite showed agents inferring all of
this from prose messages — it worked, but inference is not a contract.
Candidate: a small closed set of `error.kind` values in the declared
response schema.

## 3. State-change notification
Polling annotated pages is the only recovery/observation channel today
(and it works — see E-suite). A `data-agent-subscribe` hint (SSE/WebSocket
endpoint per resource) would replace polling where sites can afford it.
`examples/` already gestures at `data-agent-subscribe`; unspecified.

## 4. Verification / signed annotations
The trust model is self-asserted. 0.3.0 defined `verified` as reserved and
constrained endpoint origins; the real mechanism (signatures over the
canonical graph serialization — which now exists and is deterministic,
making it *signable*) is the 0.4 flagship candidate. A signed
`.well-known/agent-graph` response is a natural first step, since it avoids
the DOM-canonicalization problem entirely.

## 5. Wild-web evidence
Everything measured so far runs against this repo's own demo. Needed: one
third-party site annotated by its owner, with the agent-bench episode suite
(or a subset) run against it. The wild-web-discovery worktree
(`feature/wild-web-discovery`) has the crawling scaffold; it was never
merged. Reconcile or re-plan.

## 6. Conformance program
The validator ships in 0.3.0; a conformance *program* (badge, hosted
checker, versioned test corpus) is what makes it a coordination point
between sites and agent vendors.

## Non-goals for 0.4
- The microformats2-class syntax in `spec/advanced.md` stays non-normative.
- Economic settlement (escrow/slashing) stays out of the spec.
